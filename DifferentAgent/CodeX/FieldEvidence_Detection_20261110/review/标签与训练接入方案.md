# 标签与训练接入方案

首轮沿用现场FDR的厂商脉冲/阶跃响应，分别检测接头、末端、异常点和异常区间。物理事实单独留档；训练标签只表达响应上可辨的位置与任务。标签保留来源精度，不由峰值反推定位，不从文字推导阻抗或机理。

## 审阅器与最小数据接口

静态审阅器复用 DifferentAgent/Zcode/DG/dg_v4/fdr_io.py 的 read_fdr() 与 phase_arrays()（50–117行），读取Sweeps实测行、源S11及仪器存储的厂商ImpulseResponse/StepResponse表。阅读版exe用于展示这些表，不代表仪器内部实现。原始S11和厂商表都保留。现有read_fdr不返回SQLite rowid；读取端需取得真实Sweeps.rowid并核对phase顺序和名称。measurement_id固定为源FDR路径加真实rowid；phase_name只作显示，保留phase_index区分同名相。相名未知时保留null，不从“新的测试_4”等名称或顺序猜相别。

主输入按“同次、同测量条件的三相成组”组织，逐相保留绝对响应和相间差异；缺相用phase_mask明确标记。comparison_group_id关联这次成组输入所含的measurement_ids，并记录距离轴对齐依据；不同测次即使来自同一FDR，也不拼成一组三相。case_group表示同一物理案例，用于防止同缆数据跨训练/验证/测试集泄漏；comparison_group_id表示一次同条件三相输入，两者职责不同。标签和四任务输出仍逐measurement_id、逐相记录，只在有对应监督的相位计算损失；成组上下文不复制标签到其他相。

石杨图比记录中，A、B、C相复测对应rowid=4；C相初测rowid=3保留为独立measurement_id，不被rowid=4替换。Y方向常数平移只用于基线对齐，逐测次记录平移量；保留原始绝对step和对齐后的step，不对各相独立缩放、不去掉斜率差，也不把A/B相默认视为健康相。平滑方法等待另一agent对厂商exe的静态分析结果；目前不假设2点或15点平滑具有统一物理尺度。审阅图保留厂商原始距离轴，显示降采样只用于绘图；不自动挑峰或把文本位置投到响应曲线上。现有静态审阅包位于 scripts/build_review_packet.py，输出 output/review_packet/index.html 与 measurement_index.json。源文件只读，读取沿用Python 3.11(gpushare_cu124)和NumPy；图为内嵌SVG，不需要CUDA或额外绘图库。

最小文件清单：review/comparison_groups.json、review/accepted_labels.json、scripts/prepare_field.py、dataset.py、model.py、losses.py、train.py、evaluate.py、config/first_round.json、config/split_template.json、run_prepare.ps1、run_field_training.ps1。准备数据默认写入已忽略的output/field_cache/。

comparison_groups.json区分物理案例和模型输入组。一个物理案例可有多个比较组；case_group_id用于划分防泄漏，comparison_group_id只关联同次、同条件输入。每个成员的measurement_id使用源FDR路径和真实Sweeps.rowid，不依赖测次序号猜相。缺响应表仍保留原测次与相位成员，phase_mask由数据准备按响应表可用性生成。

accepted_labels.json按measurement_id保存事件与显式负范围。未覆盖的距离、缺相和未知标签不变成负样本；required_measurement_ids缺省为事件所属测次。start_boundary保留起点和所需上下文，首版用局部起点约束监督，不扩展为区间正例：

~~~json
{
  "measurements": [
    {
      "measurement_id": "E:\\data\\sample.fdr#Sweeps.rowid=7",
      "case_id": "case-01",
      "events": [
        {
          "task": "anomaly_point",
          "shape": "point",
          "position_m": 200,
          "required_measurement_ids": ["E:\\data\\sample.fdr#Sweeps.rowid=7"],
          "source_refs": ["ev-01"]
        }
      ],
      "negative_ranges": {
        "anomaly_point": [[100, 150]],
        "anomaly_range": []
      }
    }
  ]
}
~~~

prepare_field.py输出output/field_cache/manifest.json、groups/<comparison_group_id>.npz和独立源缓存。NPZ包含x[P,5,L]、valid[P,L]、phase_mask[P]、distance_m[L]及JSON元数据；缺失相位和缺响应表分别记录。训练/验证拆分按manifest中的case_group_id显式填写，不自动生成正式划分。

四个输出分别对应joint、terminal、anomaly_point、anomaly_range；点与区间不并为同一anomaly标签。点允许范围和区间边界按原证据表示。每个测次、每相分别保存事件；相间成组仅提供上下文，不跨相复制监督。只对证据适用且required_measurement_ids可用的相位计算损失；缺相、响应表缺失及未标相以mask排除。单相比较组设P=1，直接走同一准备、模型和训练接口，不复制成虚假的三相。确定区间内部可作正例；起点单侧边界用局部起点约束监督，不扩展成占据区间，也不猜终点。未知标签不自动当负例；负例只来自同一任务明确覆盖的范围。

## 代码接口与监督

`FieldDataset(data_dir, case_groups, training=False, single_phase_probability=0.5)`读取manifest与NPZ，返回`x`、`valid`、`phase_mask`、`distance_m`、`meta`、`target`、`supervision_mask`和`boundary_constraints`；`collate_groups`补齐batch并为边界约束添加batch_index。五通道固定为平滑脉冲signed-log、原始阶跃、平滑阶跃、平滑阶跃距离导数和归一化距离。保留各相绝对幅值与step斜率，不逐相缩放。

`PhaseDetector(in_channels=5,width=16)`返回`[B,P,4,L]` logits。P可以是1、2或3；共享单相编码器处理各相，上下文仅由comparison_group中当次可用相位提供。`case_group_id`只用于物理案例划分，`comparison_group_id`只用于成组输入；同一FDR的不同测次不拼相。

`masked_detection_loss(logits,target,supervision_mask,boundary_constraints=None)`只计算明确监督区域。石杨C相复测起点约束用anomaly_range head在起点左右各2m窗口的平均logit差构造排序损失；required_measurement_ids不齐时不计约束。它不生成区间正标签。无像素监督、无边界约束的batch跳过优化器更新；有边界约束的batch可单独更新。

`case_group_id`拆分按物理案例进行。`config/split_template.json`保持train和val为空；正式训练前由用户从`manifest.json`填写显式case_group_id。同缆复测不得跨分区。旧blind已参与多轮开发，只称开发/验证结果。

`evaluate.py`按full available context和每个单相视图分别统计。点事件按20m容差一对一匹配；required_measurement_ids不足的事件列为not_scoreable，不算FN。区间报告已知区间覆盖率/IoU，单侧起点报告起点误差。显式负范围内的背景误报计数单列；没有完整正、负审核范围时不提供看似完整的precision/F1。没有已接受监督的头标为not_scored；阈值0.5仅为开发起始值。

## 现场训练对照

A臂从随机初始化开始；B臂只有在提供兼容的共享encoder_state_dict时才运行，加载入口为`--encoder-init`。A/B采用同seed构造相同架构，使fusion与head随机权重一致；B只替换encoder。现有DG_V5是单条合成电缆，不能随机拼三条样本伪造三相真值；不默认使用旧模型checkpoint，不增加未定义的synthadapter。

首轮起始参数为epochs=40、batch_size=2、workers=0、learning_rate=3e-4、patience=8、single_phase_probability=0.5；支持标准PyTorch CUDA混合精度。这些参数尚未调优。A/B使用相同epoch预算上限、split、seed、数据顺序、相采样和验证选模/早停规则；早停使实际更新次数与完成epoch数可以不同，分别记录actual_optimizer_updates和epochs_completed。每epoch用tqdm显示batch进度，history.csv记录总损失、各head损失、有效正/负/监督点数、边界损失/约束数和学习率。保存config.json、split.json、best.pt和last.pt；best.pt按最低masked validation loss选择，不代表现场F1最优。

## 用户执行命令

准备、训练和评价都由用户执行；准备数据默认写入output/field_cache：

~~~powershell
.\run_prepare.ps1
.\run_field_training.ps1 -Arm A
conda run -n gpushare_cu124 python .\evaluate.py --checkpoint .\output\field_training\A\best.pt --data-dir .\output\field_cache
~~~

B臂依赖兼容的共享encoder checkpoint，不提供时不运行：

~~~powershell
.\run_field_training.ps1 -Arm B -EncoderInit 'D:\path\to\encoder.pt'
~~~

- B臂需用户提供兼容的共享encoder_state_dict；没有该文件时只运行A臂，不回退旧模型。
- 当前只有A02、A03、A04三个物理案例有已接受监督；正式train/val划分留空，待继续整理更多案例后由用户显式分组。
