# FDR Reader 后端响应处理链

## 结论

阅读版有两条不同路径。打开测次时，Service_Sweep 直接读取内嵌厂商响应表；缺表后不会从 S11 自动重建。用户显式执行“重新计算”命令时，MainWindow 把当前 Sweep 的 S11 与轴设置传给 Analyser.Arithmetic.GetResponse，调用嵌入的 Impulse_Response_Process.dll（Costura资源costura_win_x64.impulse_response_process.dll），再将阶跃和脉冲数组写回当前 Sweep 所属 FDR。

邦润C相初测 rowid=3 有完整 S11、没有厂商响应表。只要在派生副本中选中该 Sweep 并执行 Ctrl+R，托管调用会为它计算响应并覆盖副本中的响应表；原始FDR不会被触及。本次没有运行重算或生成曲线。

## 自动加载路径：缺表不自动回退

FDR_Reader.Service_Sweep.GetSweepData 仅处理 IsMeasured=true 的 Sweep。StepResponseOrigin 或 ImpulseResponseOrigin 为 null 时，分别调用 SQL_Sweep.GetStepResponse 和 GetImpulseResponse；FrequencyData 为 null 时，读取 MeasureData，再计算频域反射幅相与波阻抗。见 extracted/backend/Service_Sweep.cs 第7、11、13、15、17、19、21、22、23行；另一个重载从第28行开始。

SQL_Sweep.GetStepResponse 和 GetImpulseResponse 先查询 sqlite_master。响应表缺失时返回 false，out 数组为 null；表存在时按 Distance、Rho 读取并返回 true。表存在但为空时会生成0×2数组并返回true。Service_Sweep忽略getter的bool返回值；缺表时属性保持null，后续调用仍只重查表；空表时属性非null，不触发重读。该路径没有S11响应回退。见 extracted/backend/SQL_Sweep_methods.cs 第26、46行。

SQL_Sweep.GetMeasureData读取MeasureData_<rowid>的Freq、Real、Image。查询异常时显示“测试数据损坏”并返回null。Calculation.GetMagnitudePhase和GetWaveImpedanceData接到null也直接返回null。见 extracted/backend/SQL_Sweep_methods.cs 第3行和 extracted/backend/Calculation_methods.cs 第3、32行。

## 显式重算路径：当前Sweep、Ctrl+R、写入当前文件

MainWindow的RoutedCommand_Recalculate绑定Ctrl+R；命令处理器为Executed_Recalculate。它清空当前Sweep的脉冲/阶跃缓存并清图，然后启动Recalculate线程。UI资源未显示“重新计算”菜单项或按钮文字；可确认的入口是Ctrl+R。

ListBox_Sweeps_SelectionChanged将SelectedItem交给Sweep_Show，Sweep_Show把该Sweep设为CurrentSweep。因此重算作用于当前选中的单个Sweep。石杨的rowid=4 C相复测可单独选中；邦润的rowid=4名称是“新的测试_4”，相位未知，不能套用石杨映射。MainWindow.Button_LoadProject_Click将OpenFileDialog.FileName传给Service_Project.GetProject（extracted/ui/MainWindow.cs第338、340、350行）。GetProject在反编译类型输出第32行把该路径赋给Project.FilePath；随后用“SELECT rowid as RowId”读取Sweeps（第84行），将FilePath和RowId分别赋给每个Sweep（第91、92行）。所以从派生副本打开时，CurrentSweep.FilePath和Id都来自副本。相关源码位于 extracted/ui/MainWindow.cs 第311、317、437、445、1142、1154、1156、1157、1163、1164、1165行；BAML入口为 FDR_Reader.g.resources/windows/mainwindow.baml。

Recalculate读取当前Sweep内存中的MeasurementData和MeasureSetting，调用Analyser.Arithmetic.GetResponse；IL调用token确认目标类型为嵌入程序集Analyser中的Analyser.Arithmetic，不是同名的FDR_Reader.Arithmetic。MainWindow传入isMul=true，故进入Calculate_Impulse_Response_Process，DllImport目标为Impulse_Response_Process.dll（Costura资源costura_win_x64.impulse_response_process.dll）的Calculate_Impulse_Response。见 extracted/ui/Analyser.Arithmetic.cs 第8、11、12、79、94行和 MainWindow.cs 第1163行。

托管包装为native核分配一个windowPoints×3结果数组，再映射为step_response[windowPoints,2]与impulse_response[windowPoints−1,2]：第0列作为距离轴，第1列作为阶跃值，第2列作为脉冲值；脉冲输出从原结果第1行开始，因此少一个首点。GetWindowPoints(length)在length<1000时返回20000，否则取floor(length×20)，上限50000。邦润 rowid=3的X_Limit_Max为640，因此包装输出阶跃20000行、脉冲19999行。见 Analyser.Arithmetic.cs 第79、89、94、99、105、145、147行。

重算完成后，MainWindow将结果写入CurrentSweep.FilePath和Sweep.Id对应的响应表。SQL_Sweep.SaveStepResponse与SaveImpulseResponse会先DROP旧表，再CREATE并INSERT新数据；因此直接对原始FDR执行Ctrl+R会改写原文件。在主Agent准备的派生副本中执行时，写入目标是该副本。见 extracted/backend/SQL_Sweep_manual_write.cs 第3、15行和 MainWindow.cs 第1157、1164、1165行。

## 邦润C相rowid=3实际输入设置

邦润原FDR的Sweeps rowid=3名称为C相；MeasureData_3有50,000个Freq/Real/Image点，频段9kHz–1GHz。厂商ImpulseResponse_3、StepResponse_3缺失。该Sweep保存的重算输入为：

| 参数 | rowid=3保存值 | 代码使用方式 |
|---|---:|---|
| Wave_Velocity | 172.0 | MeasureSetting属性将其除以300，得到Velocity_Factor约0.5733333333；native接口收此因子；Wave_Velocity在FDR字段中未另存单位标签 |
| X_Limit_Max | 640.0 | 作为test_cable_length；UI距离轴以m显示 |
| X_Axis_Offset | 4.42465257644653 | 原值传给native；对应当前距离轴偏移 |
| Step_Uniform_Factor | 0.0 | 原值传给native，单位/标定语义未在托管代码说明 |
| Impulse_Uniform_Factor | 0.668185114860535 | 原值传给native，单位/标定语义未在托管代码说明 |
| Frequency_Start / Stop / Points | 9000 / 1000000000 / 50000 | S11表有完整50,000点；MeasureData整表传入native |

Wave_Velocity到Velocity_Factor的换算见 extracted/ui/MeasureSetting.cs 第136、149、155行。X_Limit_Max参与点数选择及native长度参数；距离偏移和两个Uniform_Factor作为独立参数传入。托管包装没有筛频、重采样或距离映射公式。

## 原生算法边界与后续复现路径

本轮静态反编译能确认native函数名、参数、输出形状和文件写入行为；频率插值/频带处理、距离坐标公式、偏移应用、幅值标定及阶跃/脉冲之间的数学关系都位于Impulse_Response_Process.dll（Costura资源costura_win_x64.impulse_response_process.dll）内，托管包装没有展示这些数值核。本次工具只反编译托管程序集；Impulse_Response_Process.dll是native资源，未还原其数值公式，也没有安装大型工具或运行DLL。接口信息不等于已还原公式。

本实验采用现成阅读版重算派生副本：打开`FieldEvidence_Detection_20261110/output/derived_fdr/邦润线_C相待重算.fdr`，选中C相后按Ctrl+R，保留原设置。副本由原件复制，作为同一物理案例的派生来源；原始测次ID保留，读取新增响应时另记副本路径和处理来源。当前副本尚未重算。

Cable-NN已有s11_to_responses可从S11实部生成响应，但未接收上述两个Uniform_Factor，不能直接称为阅读版同算法输出。当前不开发原生调用桥。

FDR_Reader.Services.Tdr.Run仍只是构造共轭对称复数数组，不执行FFT；Fftcomplex为空类。已检查的自动加载和显式重算调用均不使用它。它不解释上述native响应公式。
