再次确认：**这个 Dirty Generator 方案适用于 V1.6-Lite，也就是你 Idea 中“八、三阶段快速训练流程”的阶段一和阶段二；同时可以自然拓展到阶段三。**

但必须强调一句：**适用的是收缩后的 V1.6-DG-Lite，不是上一版“大而全”的 Dirty Generator。**
V1.6-Lite 的 Generator 目标不是一次性模拟真实世界全部复杂性，而是生成与 V1.6-Lite 输出头、hard proposal anchor、step 总长度粗估计、群时延输入、稳定化物理层完全对齐的数据集。

---

# 1. 设计总原则

V1.6-DG-Lite 应该遵守四个原则。

第一，**Generator 的 latent 参数必须和 V1.6-Lite 输出头对齐。**
你的 V1.6-Lite 第一版建议输出 $\delta_L$、$\delta_{\varepsilon,G}$、$\delta_{\alpha,G}$、$q_k$、$\Delta x_k$、$l_k$、$\delta_{\varepsilon,k}$ 和 $\delta_{\alpha,k}$，而 $\delta_g$、局部 $\tan\delta_k$、Near 残差和末端残差属于 Full 或真实微调扩展项。 所以 Generator 第一版也不应该生成过多物理自由度。

第二，**阶段一必须干净，阶段二才开始 Dirty-Lite。**
阶段一的核心是验证物理层、safe division、有界映射、导纳递推、dynamic low-pass 和最小网络闭环。你的文档明确要求阶段一限定在 $\leq2.5\ \mathrm{km}$、$K_{\max}=2$、训练频点 $1024$ 至 $2048$，Near 与末端残差保持校准主值，FiLM 关闭。 所以阶段一不该引入复杂实测污染。

第三，**阶段二服务 hard proposal anchor、slot query 和主论文结果。**
阶段二打开 hard proposal anchor、slot query、简化 cross-attention，并保留 IFFT full-grid 约 5000 点用于时延 proposal 和最终验证。 因此 Generator 必须输出 proposal pool、step 曲线、群时延、TGC 元数据、连续频率 chunk 支持和缺陷真值标签。

第四，**阶段三只扩展，不重写。**
阶段三增加长度到 $5\ \mathrm{km}$、IFFT full-grid 到 $10000+$ 点、$K_{\max}=3/4$、TGC 距离 quota、频率-距离可观测性权重和真实数据微调。你的正式路线表正是这样设计的。 所以 DG-Lite 的数据结构要预留这些字段，但阶段一/二不全开。

---

# 2. 最终推荐方案：V1.6-DG-Lite

## 2.1 Generator 名称

建议命名为：

```text
V1.6-DG-Lite: Low-Dimensional Dirty Generator for V1.6-Lite Training
```

它包含三种运行模式：

| 模式              | 对应训练阶段 | 作用                                 |
| --------------- | ------ | ---------------------------------- |
| `DG-Clean`      | 阶段一    | 最小闭环、物理层验证、无复杂污染                   |
| `DG-Dirty-Lite` | 阶段二    | V1.6-Lite 主训练，轻度 dirty，支持 proposal |
| `DG-Long-Ext`   | 阶段三扩展  | 5 km、强 TGC、真实数据微调前的鲁棒增强            |

---

# 3. 核心 latent 参数设计

## 3.1 样本级参数

阶段一和阶段二只保留这些样本级参数：

| 参数                       | 含义                     |    阶段一 |   阶段二 | 阶段三 |
| ------------------------ | ---------------------- | -----: | ----: | --: |
| `family`                 | RG58-like / power-like |     可用 |    可用 | 可扩展 |
| $L_{\mathrm{tot}}$       | 总长度                    |     开启 |    开启 |  开启 |
| $\delta_L$               | 相对 step 粗估计的长度修正       |  可生成标签 | 可生成标签 |  开启 |
| $\delta_{\varepsilon,G}$ | 背景等效介电扰动               |     开启 |    开启 |  开启 |
| $\delta_{\alpha,G}$      | 背景等效损耗扰动               |     开启 |    开启 |  开启 |
| `noise_level`            | 噪声等级                   |  关闭或极弱 |    开启 |  增强 |
| `gain_phase_level`       | 幅相测量误差等级               |  关闭或极弱 |    开启 |  增强 |
| `near_level`             | Near 污染等级              | 固定校准主值 | 小范围扰动 | 可微调 |
| `end_level`              | 末端边界非理想等级              | 固定校准主值 | 小范围扰动 | 可微调 |
| `proposal_difficulty`    | proposal 难度等级          |  关闭或极弱 |    开启 |  增强 |

这里的 `near_level` 和 `end_level` 不等于让网络第一版直接学习 Near/End 残差。阶段一和阶段二前期仍然可以把 Near/End 固定为校准主值，只在数据生成侧加入很小扰动，用于提高鲁棒性。

---

## 3.2 缺陷级参数

V1.6-Lite 阶段一和阶段二统一使用：

[
K_{\max}=2
]

每个缺陷 slot 只生成 5 个核心量：

| 参数                       | 含义       |
| ------------------------ | -------- |
| $q_k$                    | 缺陷是否存在   |
| $x_k$                    | 缺陷起点     |
| $l_k$                    | 缺陷长度     |
| $\delta_{\varepsilon,k}$ | 局部等效介电扰动 |
| $\delta_{\alpha,k}$      | 局部等效损耗扰动 |

这与 V1.6-Lite 的缺陷槽位定义一致：$q_k,x_k^{start},l_k,\delta_{\alpha,k},\delta_{\varepsilon,k}$。Full 阶段才扩展 $\delta_{\sigma,k}$ 和 $\delta_{g,k}$。

阶段一/二**不要加入**：

| 参数                  | 处理           |
| ------------------- | ------------ |
| $\delta_{g,k}$      | 阶段三或 Full 再加 |
| $\delta_{\sigma,k}$ | 阶段三或 Full 再加 |
| 局部 $\tan\delta_k$   | 后续扩展         |
| Debye 频散            | 不进入 Lite     |
| 随长度连续随机场            | 不进入 Lite     |
| 多材料复杂缺陷             | 不进入 Lite     |

否则 Generator 自由度会超过 V1.6-Lite 网络头的解释能力。

---

# 4. 数据输出结构

每条样本建议输出 6 类内容。

## 4.1 频域输入 `x_freq`

```python
x_freq = {
    "f_full": ...,              # IFFT / eval full-grid
    "f_net": ...,               # Mamba 输入网格
    "S11_obs_real": ...,
    "S11_obs_imag": ...,
    "logabs": ...,
    "sin_phase": ...,
    "cos_phase": ...,
    "diff_real": ...,
    "diff_imag": ...,
    "group_delay": ...,
    "unwrap_risk_mask": ...
}
```

你的文档中频域主分支输入正是 real、imag、log 幅值、sin/cos 相位、归一化频率、差分特征和群时延通道。 所以这些必须由 Generator/FeatureExtractor 统一生成，避免训练时临时计算带来不一致。

---

## 4.2 时延域输入 `x_time`

```python
x_time = {
    "tau": ...,
    "r_tau_real": ...,
    "r_tau_imag": ...,
    "a_tau": ...,              # 平滑包络
    "s_tau": ...,              # step 曲线
    "ds_tau": ...,             # step 差分
    "near_mask": ...,
    "end_window_mask": ...,
    "tgc_gain": ...,
    "q_step": ...
}
```

这里必须保留 step 曲线。V1.6 已经把 step 作为长电缆总长度粗估计的主依据，包络峰只作为辅助监控项。

---

## 4.3 电缆先验 `prior`

```python
prior = {
    "family": ...,
    "S_core": ...,
    "r_c0": ...,
    "r_s0": ...,
    "g0": ...,
    "eps_r0": ...,
    "tan_delta0": ...,
    "sigma_c0": ...,
    "sigma_s0": ...,
    "Z0_nominal": ...,
    "VF_nominal": ...
}
```

RG58-like 和 power-like 可以共用结构，但物理意义不同。RG58 更接近标准同轴，power-like 应解释为等效传输线参数，不要声称真实几何完全可辨识。

---

## 4.4 监督标签 `label`

```python
label = {
    "L_total": ...,
    "delta_L": ...,
    "delta_eps_G": ...,
    "delta_alpha_G": ...,

    "K_true": ...,
    "q": ...,                  # shape: [Kmax]
    "x_start": ...,            # shape: [Kmax]
    "length": ...,             # shape: [Kmax]
    "delta_eps": ...,          # shape: [Kmax]
    "delta_alpha": ...,        # shape: [Kmax]

    "segment_table": ...
}
```

阶段一和阶段二只监督这些。Near/End 标签可以保存到 meta，但不建议作为 Lite 主监督项。

---

## 4.5 proposal 输入 `proposal`

```python
proposal = {
    "x_prop": ...,             # proposal 位置
    "A_raw": ...,              # 原始包络幅值
    "A_tgc": ...,              # TGC 后幅值
    "width": ...,              # 峰宽
    "local_snr": ...,
    "distance_bin": ...,       # 近端/中段/远端
    "near_flag": ...,
    "end_distance": ...,
    "matched_defect_id": ...,
    "is_false": ...
}
```

这是阶段二的关键。V1.6 的时延辅助分支输出 $P$ 个候选 ${\hat x_p,A_p,w_p,c_p}$，hard proposal anchor 会把 slot 限制在候选附近。 所以 Generator 必须生成 proposal pool，并且要包含少量假 proposal。

---

## 4.6 mask 与 meta

```python
mask = {
    "valid_freq": ...,
    "loss_freq_mask": ...,
    "unwrap_risk": ...,
    "snr_mask": ...,
    "time_valid": ...
}

meta = {
    "generator_version": ...,
    "seed": ...,
    "mode": ...,               # DG-Clean / DG-Dirty-Lite / DG-Long-Ext
    "step_hz": ...,
    "fmin": ...,
    "fmax": ...,
    "M_full": ...,
    "dirty_level": ...,
    "quality_flags": ...
}
```

特别是 `step_hz`、`fmin`、`fmax`、`M_full` 必须保存。V1.6 中明确要求 $5\ \mathrm{km}$ 任务必须记录频率步进，且 IFFT full-grid 输出日志应包含 $f_{\min}$、$f_{\max}$、点数和 `step_hz`。

# 5. 三阶段对应配置

## 5.1 阶段一：DG-Clean

目标：**跑通 V1.6-Lite 最小闭环。**

配置：

| 项目             | 设置                                    |
| -------------- | ------------------------------------- |
| 长度范围           | $10\ \mathrm{m}$ 到 $2.5\ \mathrm{km}$ |
| $K_{\max}$     | 2                                     |
| 训练频点           | 1024 到 2048                           |
| IFFT full-grid | 约 5000 点                              |
| Near           | 固定校准主值                                |
| End            | 固定校准主值                                |
| 噪声             | 无或极弱                                  |
| 幅相误差           | 无或极弱                                  |
| proposal 假峰    | 不启用或极少                                |
| FiLM           | 不涉及                                   |
| 目标             | 验证物理层、低维参数头、长度头、slot head 能否收敛        |

阶段一 Generator 参数：

```text
L_total
delta_eps_G
delta_alpha_G
K <= 2
q_k
x_k
l_k
delta_eps_k
delta_alpha_k
```

阶段一不应该引入复杂 Dirty。否则你无法判断 loss 不下降到底是物理层问题、网络问题、proposal 问题还是数据污染问题。

---

## 5.2 阶段二：DG-Dirty-Lite

目标：**形成 V1.6-Lite 主训练数据集。**

配置：

| 项目             | 设置                                                         |
| -------------- | ---------------------------------------------------------- |
| 长度范围           | $\leq2.5\ \mathrm{km}$                                     |
| $K_{\max}$     | 2                                                          |
| 训练频点           | 2048，必要时 4096                                              |
| IFFT full-grid | 约 5000 点                                                   |
| Near           | 小范围扰动，但训练早期仍可冻结                                            |
| End            | 小范围扰动                                                      |
| 噪声             | 轻度到中度 colored noise                                        |
| 幅相误差           | 轻度幅值波纹 + 相位斜率                                              |
| proposal       | 启用 TGC、SNR、距离分层、少量假峰                                       |
| hard negative  | 必须加入                                                       |
| 目标             | 训练 hard anchor、slot query、cross-attention、频域主损失和 step 长度估计 |

阶段二新增 dirty 控制量：

```text
noise_level
gain_phase_level
near_level
end_level
proposal_difficulty
```

但这些只是“等级变量”，不要展开成十几个独立污染参数。这样 Generator 的自由度仍然受控。

阶段二样本比例建议：

| 样本类型                 |  比例 |
| -------------------- | --: |
| clean / nearly clean | 20% |
| mild dirty           | 40% |
| medium dirty         | 25% |
| hard negative        | 15% |

hard negative 包括：

```text
无缺陷但 Near 较强
无缺陷但 step 有旁瓣
无缺陷但存在假 proposal
弱远端缺陷
长而弱的分布式缺陷
两个近距离缺陷被 proposal 合并
```

这一步很关键。因为 hard proposal anchor 如果只见过“正确 proposal”，实测时会被夹具、接头、旁瓣、噪声峰带偏。

---

## 5.3 阶段三：DG-Long-Ext

目标：**从 V1.6-Lite 平滑扩展到 5 km 和真实数据微调。**

配置：

| 项目                       | 设置                                    |
| ------------------------ | ------------------------------------- |
| 长度范围                     | $2.5\ \mathrm{km}$ 到 $5\ \mathrm{km}$ |
| $K_{\max}$               | 3 或 4                                 |
| 训练频点                     | 2048 到 4096                           |
| IFFT full-grid           | 10000 点或更多                            |
| TGC                      | 增强                                    |
| 距离 quota                 | 启用                                    |
| 频率-距离可观测性                | 启用                                    |
| RG58 接头伪峰                | 可加入                                   |
| source match/directivity | 少量加入                                  |
| 真实数据微调                   | 接入 RG58 和电力电缆                         |

阶段三扩展字段：

```text
w_obs(f, x)
distance_quota_id
strong_tgc_flag
connector_artifact_flag
real_domain_style_id
```

阶段三可以加入：

| 扩展项                           | 是否建议          |
| ----------------------------- | ------------- |
| $K_{\max}=3/4$                | 建议            |
| $5\ \mathrm{km}$ step_hz 校验   | 必须            |
| 强 TGC                         | 必须            |
| 频率-距离 mask                    | 必须            |
| RG58 接头伪峰                     | 建议            |
| source match/directivity 简化模型 | 可少量加入         |
| $\delta_g$、$\delta_{\sigma}$  | 只在 Full 消融中加入 |
| 局部 $\tan\delta_k$             | 暂不建议优先加入      |

# 6. 生成流程

V1.6-DG-Lite 的单条样本生成流程建议固定为：

```text
1. 选择 mode: DG-Clean / DG-Dirty-Lite / DG-Long-Ext
2. 采样 cable family: RG58-like / power-like
3. 采样频率网格 f_full, f_net, f_loss
4. 采样 L_total, delta_eps_G, delta_alpha_G
5. 采样 K_true, x_k, l_k, delta_eps_k, delta_alpha_k
6. 构造有序分段表 segment_table
7. 根据 Lite RLGC 模型生成 S11_clean(f)
8. 加入 Near/End 主值或轻度扰动
9. 根据 mode 加入 dirty measurement wrapper
10. 得到 S11_obs(f)
11. 计算 group delay 与 unwrap risk mask
12. 计算 IFFT r(tau)
13. 计算 envelope a(tau)
14. 计算 step s(tau), ds(tau), tau_end_step, q_step
15. 执行 TGC proposal extraction
16. proposal 与真实缺陷匹配
17. 生成 x_freq, x_time, prior, label, proposal, mask, meta
18. 执行 quality gate
19. 写入 shard
```

---

# 7. 第一版不要加入的内容

为了保证 V1.6-Lite 可训练、可调试、可解释，以下内容第一版应冻结或删除：

| 内容                          | 第一版处理               |
| --------------------------- | ------------------- |
| $\delta_g$                  | 不加入                 |
| $\delta_{\sigma,k}$         | 不加入                 |
| 局部 $\tan\delta_k$           | 不加入                 |
| Debye 频散                    | 不加入                 |
| 低频漏电                        | 不加入                 |
| 连续随机场背景                     | 不加入                 |
| 完整 VNA 三误差模型                | 不加入                 |
| 复杂 source match/directivity | 阶段三少量加入             |
| 频点缺失/outlier spike          | 阶段三再加入              |
| 多窗口随机 IFFT                  | 第一版固定 Hann 或 Kaiser |
| 大量 RG58 接头模型                | 阶段三或真实适配再加          |
| $K_{\max}=4$                | 阶段三再加               |

你之前担心“参数量太大”是正确的。第一版 Generator 应该把自由度压在 **15 到 20 个有效 latent 参数**内，而不是 50 个以上。

# 9. 最终确认结论

**可以确认：V1.6-DG-Lite 是适配你的 V1.6-Lite 阶段一和阶段二的 Dirty Generator。**

它的核心是：

```text
低维物理 latent
+
有限段传输线 clean forward
+
轻度 dirty measurement wrapper
+
step 总长度粗估计
+
group delay 输入
+
TGC proposal pool
+
hard negative proposal
+
完整标签和 mask
```

它对阶段一的作用是：

```text
验证最小闭环、物理层稳定性、低维参数头和基本监督标签。
```

它对阶段二的作用是：

```text
训练 hard proposal anchor、slot query、cross-attention、step 长度估计、频域主损失和缺陷定位。
```

它对阶段三的扩展方式是：

```text
把 Kmax 从 2 提升到 3/4；
把 full-grid 从约 5000 点提升到 10000+；
把长度从 2.5 km 扩展到 5 km；
加入强 TGC、距离 quota、频率-距离可观测性 mask；
再接入 RG58 measurement style 和电力电缆真实数据微调。
```

因此，最终版本不应该叫“大型 Dirty Generator”，而应该叫：

```text
V1.6-DG-Lite：面向 V1.6-Lite 三阶段训练的低维可扩展 Dirty Generator
```

这个方案既不会把参数空间炸开，又能严格服务你当前 V1.6 的阶段一、阶段二，并为阶段三保留自然升级路径。
